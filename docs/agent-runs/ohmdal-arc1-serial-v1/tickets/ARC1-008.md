## Objetivo verificable

El ciclo completo `mount → pause → resume → destroy` del laboratorio, **a través del `RuntimeHost`
real con el `hd2dRuntime` real**, funciona sin excepciones, deja el contenedor vacío, y el heap no
crece más de **512 kB por ciclo `mount → destroy`**. El gate lo fija `SCENE_BUDGETS.md` §4.3 vía
`CP-020`; este ticket lo mide por primera vez y no puede cambiarlo.

## Qué exige el canon, literalmente

- `tasks.json`, `ARC1-008`: *«Probar mount pause resume destroy y fugas»*.
- `SCENE_BUDGETS.md` §4.3: *«≤ 512 kB por ciclo mount→destroy»* — heredado en `STATE.md` línea 105 y
  en las notas de `ownership.json`.
- `STATE.md`: el recorrido determinista produce `db322500` en 1440×900 y `50543361` en 390×844 desde
  `aeb9f70`. Si este ticket los ve cambiar, es una regresión de `ARC1-007`, no un artefacto de medición.
- `H3_CONTRACT.md` §3: `src/jugar/**` prohibido de plano.

## Decisiones de método (`CP-026`)

1. **Driver:** navegador embebido de Orca (`orca goto/eval/console/screenshot`) contra `vite dev` en
   el puerto 5199. Playwright permanece excluido: el usuario rechazó su reinstalación al cerrar
   `ARC1-007`, y esta corrida no la reabre.
2. **Ciclo por el host real:** `RuntimeHost` gana `pause()`/`resume()` por delegación al handle
   activo (aditivo; `tests/a1-runtime-host.test.ts` pasa sin tocarse).
3. **Sonda de control:** la página dev del laboratorio expone `window.labControl`
   (`start/pause/resume/destroy/status`). No es entrada del build de producción (`CP-020`).
4. **Protocolo de fugas:** heap por `performance.memory.usedJSHeapSize` en el mismo punto de fase de
   cada ciclo, warmup + N ≥ 5 ciclos, crecimiento por ciclo ≤ 512 kB, muestras crudas en evidencia.
5. **Factibilidad verificada** el 2026-08-04: la página monta, las sondas responden y el heap es
   legible desde `orca eval`.

## Condiciones exactas para `DONE`

- un ciclo `mount → pause → resume → destroy` por el host real deja `#app` vacío,
  `activeRuntime()` en `null` y cero errores de consola;
- un segundo `mount` sobre el mismo contenedor funciona;
- `pause` detiene el tiempo simulado y `resume` lo continúa sin salto de `dt`, medido con sondas;
- la fuga por ciclo es ≤ 512 kB, medida sobre ≥ 5 ciclos con warmup y muestras crudas;
- los digests del recorrido determinista no cambian (paquete B): `db322500` en 1440×900 y
  `50543361` en 390×844;
- `npm run build`, `npm test` y `git diff --check` PASS; `npm run verify` se declara `not-run`;
- diff dentro del ownership declarado arriba;
- todo hallazgo ajeno queda en `OPEN_ISSUES.md` y no se arregla;
- commit acotado a nivel de ticket, con autorización del usuario.

## Gate humano

disco (`OI-006`) y el usuario autoriza el commit al cerrar. Si el build introdujera un cambio
visible, el paquete se detiene y lo reporta.

y su reversión no afecta al shell publicado ni a `/jugar`. No se borra evidencia ni se reescribe
historia.
