# `ARC1-008-A` — Ciclo de vida real y gate de fugas de 512 kB

**Ticket:** `ARC1-008` — Probar mount pause resume destroy y fugas
**Ruta de modelo:** `claude` — `claude-sonnet-5` para el build, Orquestador para la medición
(`CP-028`; el contrato original decía `opencode-go/deepseek-v4-flash`)
**Estado:** `DONE`
**Gate humano:** no — el paquete no introduce cambio visible
**Presupuesto:** 1 implementación + 1 corrección
**Estimación:** 60–90 min

## Objetivo

El ciclo completo `mount → pause → resume → destroy` queda ejercido a través del `RuntimeHost`
real y el gate de fugas de 512 kB por ciclo queda medido, con evidencia reproducible en disco.

## Terminado cuando

- `RuntimeHost.pause()` y `RuntimeHost.resume()` existen como delegación al handle activo; sin
  runtime montado son no-op; `tests/a1-runtime-host.test.ts` pasa **sin modificaciones**;
- la página del laboratorio expone `window.labControl` con `start/pause/resume/destroy/status`
  atado al host creado en `main.ts`;
- un ciclo por el host real termina con `#app` vacío, `activeRuntime()` en `null` y 0 errores de
  consola; un segundo `mount` sobre el mismo contenedor funciona;
- `pause` detiene el tiempo simulado y `resume` lo continúa sin salto de `dt`: verificado con dos
  snapshots de `render_game_to_text()` alrededor de cada transición;
- la fuga está medida sobre ≥ 5 ciclos con 1 ciclo de warmup: heap por
  `performance.memory.usedJSHeapSize` muestreado en el mismo punto de fase (tras `destroy` + 2 s de
  pausa), crecimiento **≤ 512 kB por ciclo**;
- existe evidencia según la sección `Evidencia`;
- `npm run build` PASS;
- `npm test` PASS;
- `git diff --check` PASS.

Cada criterio se responde con un comando, una medición o un archivo. Ninguno se responde con una
opinión.

## Ejecución

Una estrategia técnica, una implementación:

1. Agregar `pause()`/`resume()` a `RuntimeHost` como delegación al handle activo. Correr
   `npm test`: `a1-runtime-host` debe pasar sin tocarse.
2. Exponer `window.labControl` en `main.ts` del laboratorio, atado al host existente. Sin efectos
   de nivel superior nuevos.
3. Confirmar el servidor de desarrollo en el puerto 5199 (`npm run dev -- --port 5199 --strictPort`
   si no está corriendo) y la página `http://localhost:5199/labs/ohmdal-hd2d-preprod/` montada en el
   navegador embebido de Orca (`orca tab list` / `orca eval`).
4. Medir con `orca eval` en el contexto de la página:
   - estado inicial del heap;
   - `pause` → snapshot, `resume` → snapshot: verificar detención y continuidad sin salto de `dt`;
   - warmup: 1 ciclo `destroy → start`;
   - N ≥ 5 ciclos `destroy → muestra de heap + 2 s de pausa → start`, muestra de heap en el mismo
     punto de fase de cada ciclo;
   - consola tras cada ciclo (`orca console`), conteo de errores.
5. Escribir la evidencia (sección `Evidencia`) con las muestras crudas, los deltas por ciclo, el
   crecimiento medio y el veredicto contra 512 kB, y los comandos exactos de reproducción.
6. `npm run build`, `npm test`, `git diff --check`.

## Detenerse cuando

- el crecimiento por ciclo supera 512 kB: se registra y se reporta; **no** se modifica la
  simulación ni el `dispose()` para «arreglar» la fuga — eso es hallazgo, no alcance;
- el navegador de Orca no puede conducir la página o leer el heap: `BLOCKED`, sin improvisar un
  segundo driver;
- hace falta modificar algo fuera de `Permitido`;
- `tests/a1-runtime-host.test.ts` falla por la delegación;
- aparece una contradicción con el canon congelado;
- se agotó el presupuesto de rondas.

**Se corrieron 16 ciclos y no 5** porque las primeras 5 muestras mostraron ±2 MB de varianza entre
ciclos consecutivos: con ese ruido, cinco puntos no distinguen una fuga de 512 kB del calendario del
recolector. Subir N no cambia el gate ni el protocolo, sólo el tamaño de muestra.

**Review independiente: `APROBADO CON P2`**, cero P0 y cero P1. El reviewer recalculó los tres
estimadores de fuga desde las muestras crudas con su propio script y los tres coinciden con lo
publicado; verificó contra `dist/` que `labControl` no se publica (`grep -rl labControl dist/` sin
resultados); y trazó a mano las tres ventanas de `current` para descartar carrera. Sus dos P2 son
`OI-015` —la captura faltante, ya declarada— y `OI-017` —el estado de pausa no sobrevive a un cambio
de runtime—.

**Es el primer paquete de esta corrida cuya fase `review` corrió de verdad**, como sesión separada
que re-verificó el trabajo. `ARC1-004` a `ARC1-007` tuvieron que declarar «no hubo review
independiente»; acá lo hubo. **Pero no es independiente por modelo:** builder y reviewer corrieron
los dos con `claude-sonnet-5`, que es la condición que `DEV-001` marca. Declarado como `DEV-003`, y
